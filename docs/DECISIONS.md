# 决策记录

- 决策：vendor/libghostty-rs 置于仓库根（而非 vt-verify/vendor 下）。否决方案：保留嵌套路径——vt-verify 是冻结验证基线，骨架 crate 的 path 依赖不应指向被冻结目录内部。已验证事实：2a 阶段 git mv 提升后 v3/v4 回归通过。
- 决策：构建路径全部经环境变量（ZIG/GHOSTTY_SOURCE_DIR/GHOSTTY_ZIG_SYSTEM_DIR）传入，脚本未设置即报错。已验证事实：仓库内 grep 无 /root/Desktop 绝对路径残留。
- 决策：close() 契约为先释放 PTY 主端再回收子进程；读线程 join 带 5s 超时。依据：Windows 侧验证数据（先等子进程退出会使主端 EOF 延迟约 83s）；Unix 同样遵守。待验证假设：该 83s 数据在 Windows 侧的复现条件，Linux 侧未复现该延迟。
- 决策：FrameSnapshot 为完全自有类型，不含 libghostty 类型。依据：规格要求快照可被 render/app 独立持有。已验证事实：snapshot.rs 仅含自有结构体。
- 决策：骨架阶段 CpuRenderer::render 为占位实现，softbuffer/fontdb/fontdue 接线在实现阶段完成。依据：规格将渲染实现列入阶段（三）。待验证假设：Devuan 5 本机具备 softbuffer 所需的 X11/EGL 开发库（cargo check 时验证）。
- 决策：依赖版本不固定精确号（Cargo.toml 用宽松要求），与规格一致。已验证事实：portable-pty 0.8.1 与 vt-verify 基线一致。
- 未解决问题：winit/softbuffer/fontdb/fontdue 的实际解析版本以 Cargo.lock 为准（骨架提交时落盘）。
- 决策：app 事件循环用 winit 0.30 的 run_app + ApplicationHandler（EventLoop::run/create_window 在 0.30.13 已 deprecated，clippy -D warnings 不可留）。已验证事实：clippy --workspace --all-targets -D warnings 通过。
- 决策：softbuffer Context 用 EventLoop::owned_display_handle 创建，Surface 用 Rc<Window> 共享句柄，规避闭包自引用借用冲突。已验证事实：编译通过。
- 决策：键盘映射为阶段1 子集（NamedKey 命名键 + ASCII 字母数字，其余忽略）。工程判断：全量键位映射超出阶段1 范围。
- 决策：阶段1 网格像素尺寸固定 8x16（CELL_W/CELL_H），字体度量接入留待后续阶段。工程判断。
- 决策：render 每格光栅化首字符（等宽网格假设），宽字符续格不单独画。已验证事实：合成快照像素断言通过；真实宽字符渲染效果列入 PHASE1-LINUX.md 手动清单。
- 决策：on_pty_write 回调经 channel 中转写 PTY（回调在 feed 调用栈内同步触发，不能直接借用 writer）。已验证事实：编译+接线结构通过；运行级验证列入手动清单。
- 决策：app 增加 bin 入口（src/main.rs），shell 取自 SHELL 环境变量、未设置回退 /bin/sh。已验证事实：clippy --all-targets 通过。
- 决策：pty 测试中 writer() 借用与写操作在同一表达式内完成，避免跨语句可变借用冲突。工程判断。
- 未解决问题：app 事件循环无运行级自动化测试（容器无显示器）；GUI 行为列手动清单。
- 已验证事实：依赖解析版本 winit 0.30.13 / softbuffer 0.4.8 / fontdb 0.21.0 / fontdue 0.9.5 / portable-pty 0.8.1 / anyhow 1（Cargo.lock）。
- 问题（已验证事实）：合并 win 分支后 crates/pty/tests/pty_windows.rs 缺文件级 cfg 门控，引用 pty::windows::join_thread_timeout / WindowsPty::resolve_program / NativePty::child_pid，Linux 上 cargo test --workspace 编译失败（E0432/E0433/E0599 四处）；cargo build --workspace 不受影响（不编译 tests）。
- 处理（已验证事实）：用户裁决 C 明示豁免"不得编辑 Windows 专属文件"限制，仅限一处——pty_windows.rs 头部加 #![cfg(windows)]（与 pty_unix.rs 的 #![cfg(unix)] 对称），不做其他修改；提交信息 "shared: gate pty_windows.rs with cfg(windows) (user-approved exemption)"。
- 影响（工程判断）：Windows 侧 merge origin/main 时该文件头部已有 #![cfg(windows)]，若其后续编辑覆盖头部需保留门控；豁免仅此一处，不构成先例。
- 已验证事实：门控提交因 edit 与 bash 并行竞态晚于 DECISIONS 登记提交（49c61bc 仅含登记），门控改动以同信息单独补提交；后续步骤先确认落盘再暂存，避免同类竞态。
- 决策：render 字体查询用 fontdb generic 链 [Family::Monospace, Family::Name(family)]（Query.families 优先列表）。已验证事实：fontdb 0.21 的 Family::Name 不解析 fontconfig "monospace" 别名（office-pc 实测 family 'monospace' not found in system fonts 致 app panic）；Family::Monospace 由 fontdb 按 generic 解析。
- 决策：app resumed 启动失败路径（create_window/softbuffer context/surface/VtTerminal::new/pty spawn/take_reader/on_pty_write/CpuRenderer::new）由 expect panic 改为 eprintln 记录 + return 退出事件循环；读线程句柄在 spawn 后立即存入 handler，失败路径由 run() 尾部 join_thread_timeout + close 清理。依据：编码约束（外部输入/系统调用覆盖失败路径）。已验证事实：cargo check --workspace --all-targets 通过；office-pc 字体缺失场景的优雅退出为本设计目标（本开发机字体齐备未复现 panic 路径，工程判断）。
- 决策：main.rs 补齐规格 2b 的 --font/--font-size 命令行覆盖（阶段1 骨架遗留），并加 APP_COLS/APP_ROWS/APP_FONT_FAMILY/APP_FONT_SIZE 环境变量层；优先级 CLI > 环境变量 > 默认常量；数值解析失败回落默认（外部输入校验）。已验证事实：cargo check 通过。
- 偏差登记：规格 2b 仅提命令行 --font/--font-size；实现为 CLI 优先于环境变量的双层（工程判断：批处理场景以环境变量注入更简洁）。
- 根因（已验证事实）：app 输入无回显缺陷经 Xvfb+e2e 插桩逐段实测——a 点 winit KeyboardInput 16 条正常（text=Some("e")）；b 点 KeyEncoder encoded 0B（字母键经 KeyEncoder 编码需 event unshifted codepoint，app 侧未设时输出空字节）；c 点写 PTY 0B；d-g 点链路正常（PTY 读线程收 shell 输出、feed、snapshot 非空、present ok 均有日志）。

- 修复（已验证事实）：softbuffer 初始尺寸——resumed 里 surface 创建后立即 resize 到 window.inner_size()（Xvfb 复现 "Must set size of surface before calling present()" panic）。
- 修复（已验证事实）：渲染尺寸取缓存 last_size（resumed/Resized 更新），窗口销毁后不再调 window.inner_size()（winit 0.30.13 x11 window.rs:1248 GetGeometry unwrap panic）。
